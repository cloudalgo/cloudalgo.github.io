Six ways the ember button can answer a cursor.

The button itself does not change — same ember fill, same square corner, same #110605 label at 6.17:1. What changes is the half-second after the pointer lands on it. Every option below is live: hover each pair, and press them to feel the active state. The outline button beside each one is there to check the pairing, since both share .btn.

Each option also has to answer a visitor who has asked their machine for less motion. Flip this to see the fallback each one lands on.

01

Ink wipe

Ink strokes across the fill from left to right and the label goes to paper behind it. The same gesture the hero underline already makes when the page loads, moved onto the thing you click.

02

Press block

The button lifts off the page and a hard ink block appears underneath it — no blur, no softness, a shape rather than a shadow. Pressing drops it flat again in 60ms. Square corners are what make this read as a printing block instead of a floating card.

What I would ship

02 Press block, with 06 Ember deepen underneath it. They are not rivals — one is movement and one is colour, and together they cost eight lines and no markup.

  1. Press block is the only option that is about the button being a physical thing. Square corners, hard ink, no blur: it is the press-room argument applied to an interaction instead of a border. It also fixes something that is currently missing site-wide — nothing on this site has a pressed state, so every button feels like an image until it navigates.
  2. Ember deepen retires opacity: 0.8, which is the actual defect in today's hover: fading the fill toward the paper drops the label's contrast below AA for as long as the pointer is on it. Stepping to accent-600 keeps it at 5.54:1.
  3. Ink wipe is the one to pick instead if you want the fold to have a signature move rather than a well-behaved one. It costs a markup change and it is the boldest thing on the page — which is an argument for it and against it.

Whichever you pick, the timings go in tokens/_components.scss as --btn-hover-* knobs beside the --mark-draw-* ones, so a future theme can slow the whole site's motion in one edit.
