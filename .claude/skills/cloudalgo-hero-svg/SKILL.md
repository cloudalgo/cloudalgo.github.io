# Hero art for the Journal

Every post gets a 1200×600 SVG at `public/blog-images/<slug>-hero.svg`. They are
written by hand, not generated by an image model, because the house style is a
diagram of the thing the post is about — not a picture of a laptop.

## Read one first

Read an existing hero before writing a new one. They share a skeleton:

- `orgvitals-hero.svg` — a grade ring and score, category bars, findings list
- `apex-lint-hero.svg` — a terminal window, lint output, rule list
- `salesforce-field-impact-hero.svg` — a terminal window, dependency output
- `airflow-postgres-schema-database-rename-hero.svg` — a code before/after, a fallback chain
- `salesforce-soap-login-retirement-audit-hero.svg` — a query result table, a caller list
- `heroku-connect-at-scale-hero.svg` — a mapping console with two flagged rows, a five-row findings list

## The skeleton

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1200 600" aria-hidden="true">
  <rect width="1200" height="600" fill="#F7F4F2"/>
  <line x1="578" y1="40" x2="578" y2="560" stroke="#F75A41" stroke-opacity="0.34" stroke-width="1"/>
  <!-- LEFT: the artefact  -->
  <!-- RIGHT: what it found -->
</svg>
```

A two-panel split at x≈578. Left is the thing (a terminal, a report card, a
config, a payload). Right is the consequence (findings, a list, a diff, a
flow). If the post has no natural two-panel shape, a single full-width diagram
is allowed, but keep the same palette and density.

## Palette — the site's own tokens, at reading contrast

| Use | Value |
| --- | --- |
| Ground | `#F7F4F2` (`paper-100`) |
| Ink | `#131110` (`ink-900`) at varying `fill-opacity` |
| Panel fill | `#FFFFFF` (`paper-000`), solid |
| Panel border | `#131110` at `0.15`, `stroke-width="1.5"`, `rx="12"` |
| Reversed type, inside an ink panel | `#F7F4F2` at `0.78`–`0.95` |
| Rules, dividers, connectors | `#F75A41` (`accent-500`) — see below |

The ground is `paper-100` and the panels are `paper-000` because the page
itself is `paper-000`: a warm ground with white cards on it reads as a mounted
plate, where the old `#F5F5F2` slab read as a grey hole in a white page.

**Opacity ladder for ink type**, every rung measured against the `#F7F4F2`
ground:

| Rung | `fill-opacity` | Contrast |
| --- | --- | --- |
| Primary | `1.0` | 18.6:1 |
| Strong | `0.92` | 14.3:1 |
| Body | `0.86` | 11.8:1 |
| Secondary | `0.80` | 9.7:1 |
| Tertiary | `0.74` | 7.8:1 |
| Labels, captions | `0.68` | 6.3:1 |
| Faintest type on the plate | `0.62` | 5.1:1 |

`0.62` is the floor, and it is a floor rather than a suggestion: below it the
type stops clearing WCAG AA, and these drawings are also cropped into the
social card, where they are read at 456px wide. Non-type furniture is exempt —
empty tracks and panel tints stay at `0.06`–`0.16`, because they are ground,
not content.

**Lines carry the brand band.** Every rule, divider, arrow shaft and arrowhead
is `#F75A41` at `0.34` (hairline) to `0.70` (a connector the eye must follow).
Panel borders and box outlines stay ink — they are edges, not lines, and sixty
coral outlines is a mess. Fills stay ink too; the ember is never a background.

**Every hero must highlight something with the ember**, and a hairline rule
does not count: at `0.34` on a warm ground it is barely a tint, so a drawing
whose only coral is its centre divider reads as monochrome. At least one
element has to be unmistakably `#F75A41` and has to be pointing at the thing
the post is about.

The device that works is the **severity marker** — a `width="4"` bar down the
left edge of a finding row, its opacity carrying the severity:

```xml
<rect x="668" y="128" width="4" height="40" rx="2" fill="#F75A41" fill-opacity="0.70"/>
```

`0.70` / `0.58` / `0.46` for the three steps. Where a post has no findings
list, the equivalent is a flagged table row, a marked-up token in a code
panel, or the single number the whole drawing exists to show. Pick the one
element a reader should land on first and give that the ember; giving it to
six is the same as giving it to none.

**No watermark, no logo lockup.** One was built and rejected — a mark in the
corner buys attribution the site does not need on its own pages, and it does
not stop anyone copying an SVG whose source is right there in the file. The
art carries the brand through the palette, not through a badge.

## Type

```
font-family="Archivo, Outfit, system-ui, sans-serif"
font-family="'Courier New', Courier, monospace"   <!-- terminal / code content -->
```

**These render as `<img>`, so no webfont loads and the browser falls back to a
system face.** Design for that: keep type large and bold, do not rely on the
exact metrics of Archivo, and leave generous padding so a wider fallback face
does not collide with the next element.

Scale that works:

- Eyebrow label — `font-size="15"`, `font-weight="700"`,
  `letter-spacing="0.14em"`, uppercase, `fill-opacity="0.68"`
- Hero numeral — `font-size="96"`, `font-weight="900"`, `fill-opacity="1"`
- Row title — `font-size="18"`, `font-weight="600"`, `fill-opacity="0.92"`
- Row detail — `font-size="13"`, `fill-opacity="0.74"`
- Right-aligned tag — `font-size="12"`, `font-weight="700"`,
  `letter-spacing="0.06em"`, `fill-opacity="0.68"`, `text-anchor="end"`

## Content rules

The art must show **real, specific content from the post**. Not lorem, not
placeholder. If the post is about a governor limit, the terminal shows the
actual error. If it is about a retirement notice, the panel shows the actual
API version. Someone should be able to read the hero and know what the post
argues.

Never invent a client name, a metric or a log line that implies a real
engagement. Generic org names (`Acme`, `acme-prod`) are fine.

## Budget

Keep it under about 20KB. The existing six run 5.7KB to 14.2KB.
Every element is hand-placed — no `<foreignObject>`, no embedded raster, no
external references, no `<style>` block, no scripts. Set `aria-hidden="true"`
since the post's alt text comes from the frontmatter.

## Verify

Well-formed first:

```bash
python3 -c "import xml.dom.minidom; xml.dom.minidom.parse('public/blog-images/<slug>-hero.svg')" && echo "well formed"
```

Then confirm nothing overflows the 1200×600 box: every `x` under about 1160,
every `y` under about 570.

**Then render it and look at it.** This is not optional and the two checks
above do not replace it. Both real defects this art has shipped — a retone
that lightened the one element it was meant to darken, and a regex that
silently skipped every `<line>` in the file — parsed clean, stayed inside the
box, and were only ever going to be caught by a pair of eyes:

```bash
node scripts/render-svg.mjs public/blog-images/<slug>-hero.svg
```

It prints the path it wrote. Pass a second argument to choose one.

Read the PNG. Check the ember lands where you meant it to, that no fallback
face has collided with its neighbour, and that the drawing still says what the
post says.

## Optional short video

Only where a post genuinely suits motion — a product demo, a before/after, a
flow that is hard to read statically. Cap it at a few per week; it costs
credits. Static SVG remains the frontmatter `image:` regardless; a video is
distribution material for LinkedIn, not the post hero.
